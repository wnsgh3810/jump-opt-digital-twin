**정의 (사용자 확정, 2회 지적 후)**: **점프높이 = 지면(z=0)에서 베이스 중심까지 높이의 최댓값.**
- 실측 출처: 각 trial 폴더의 `Real Data.txt` → `"실제 점프 높이 : X m"` (예: 0.82m).
- sim 대응: `base_z` 최댓값 (모델에서 base_z = 지면 기준 베이스 중심 높이).
- 심판 스크립트: `<repo>/code/goal23_fullspan/_F_jumph_abs.py` (ModeA 재생을 이륙 후 +0.6s 연장해 직접 읽음).

**Why (금지 사항)**: `_D_jumph.json`의 GRF 체공시간 기반 `h = g·T²/8`은 **상승분**이지 점프높이가
아니다. 이 둘을 혼동해 마라톤 D·E·F에 걸쳐 **"점프높이 8~25cm 과대(×1.2~1.5)"**가 반복 기록됐고,
올바른 정의로 재니 **평균 배율 1.003 · |Δh| 4.31cm = 사실상 정확**이었다. 잘못된 지표 위에서
"지지층 에너지 과잉" 서사와 이월 항목이 세워졌다.

**How to apply**: ①점프높이는 항상 `_F_jumph_abs.py`로 잰다 ②`_D_jumph.json`은 **이륙 타이밍 검출
전용**, 높이 지표로 쓰지 말 것 ③속도로 환산(v²/2g)하지 말고 **시간을 늘려 최고점을 직접 읽는다**
(유도량 대신 직접 관측량 — 사용자 지시) ④남은 과제는 전역 과대가 아니라 **세션 편차**
(0424 ×0.900 부족 ↔ 24일 ×1.173 과대). ⑤`26.03.24/P100_D3`의 Real Data.txt만 단위가 cm(74.000).

**★ 출처 등급 (사용자 확정 08-07): `실제 점프 높이` = 영상으로 잰 값 = A급 실측.**
같은 파일의 다른 값들은 **전부 프로그램 추정값이라 믿지 말 것** — 특히 `Expected Maximum Jump
State` 블록의 `Estimated final jump height`(적힌 값과 45개 중 15개만 일치, 최대 0.17m 차)와
`Base vertical velocity`. **GRF 체공시간 경로도 높이 지표 금지**: h_체공/h_영상 = 0.919 로 8% 과소
(레일 마찰·착지 자세차 → 체공이 짧아짐). 데이터 사전의 "GRF 상대 타이밍 전용" 규칙과 정합.
26.03.24/P100_D3 만 `074m` 표기(소수점 누락) — 파서에서 방어 필요.

**A급이 주는 것 (08-07 `_G10c_anchor.py`)**: 영상 h 로 이지 CoM 속도를 역산하면
ż_영상/ż_운동학 = **1.021** [0.95, 1.13] → **트윈 CoM 야코비안이 2% 안에서 정확**함이
외부 계측으로 검증된다. 이 앵커 위에서 푸시 실효토크 = **1.33×a_hat = 0.75×G5정본** 확정.

★ **0.84m 는 솟은 양이 아니라 절대 높이** — 이지 시점 베이스가 이미 0.40~0.48m 라 **실제 상승은
31~36cm**. 이 혼동이 3회째다.

**★ 갱신 (마라톤G G42, 08-08) — 계통 편향 소멸**: 마라톤G 기록 구성에서 45 trial 을 재니
`h_sim/h_영상` **평균 1.0003 · 중앙 1.0010 · 과대 23건 / 과소 22건**. 즉 **편향은 0** 이고
남은 4.37% 는 **전부 산포**다. 위 ④의 "세션 편차"만 잔여 과제이며, 마라톤D 계열에 기록된
"점프높이 sim 과대"는 **더 이상 사실이 아니다** — 그 문장을 근거로 인용하지 말 것.
부작용: 편향이 0 이라 **질량을 단독으로 늘리면 반드시 악화**한다 (h_sim 이 1 아래로). 질량은
토크 척도와 축퇴이므로 **캡과 함께** 움직여야 한다 ([[marathon-g-transmission-260808]] G43).
