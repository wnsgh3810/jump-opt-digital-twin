**사건 (2026-08-02)**: 점프높이 지표가 **정의부터 틀린 채** 마라톤 D·E·F 세 번에 걸쳐 1급 지표로
쓰였다. 실험실 정의는 **지면 기준 베이스 중심 최고높이**(`Real Data.txt` "실제 점프 높이", 0.82m)인데,
나는 `_D_jumph.json`(GRF 체공시간 → 상승분 g·T²/8, ~30cm)을 실측으로 승계했다. 올바른 정의로는
**배율 1.003 = 사실상 정확**인데 "8~25cm 과대"로 3개 마라톤의 서사·축·이월이 세워졌다.

**근본 원인 (compaction이 아니다)**: 마라톤 D P17에서 **이미 충돌을 발견했다** —
"Real Data.txt 0.82m = 절대 정점, 내 판독 0.31m = 상승분"까지 적어놓고, **"기립 0.5m + 0.31 ≈ 0.81
이니 모순 아님"으로 합리화**하고 넘어갔다. 지표를 실험실 정의로 교체하는 대신 내 지표를 방어한 것.
그 뒤 압축을 거치며 합리화했다는 사실조차 사라지고 "|Δh|"만 기정사실로 승계됐다.

**같은 패턴의 재발 (전부 사용자가 물리적 실제를 가리켜 잡음)**: 발이 트윈에서 고정이라 단정(E-H1,
코드 미확인) · 영상 슬립을 하강 구간만 재고 "복원 완료" 보고(옛 "24fps 불가" 결론 무재검) ·
발이동을 슬립이라 명명(D P13 선행 판정 망각) · 로봇 질량 3.20 추정치 방치(실측 3.26).
**공통점: 원본보다 내 이전 서술을 신뢰했다.**

**How to apply**
1. **지표를 쓰기 전 원본에서 한 번 직접 재유도**한다. 파생 JSON(`_D_*.json` 등)은 원본 대조 없이
   실측으로 쓰지 않는다. 원본 = 각 trial 폴더의 `Real Data.txt`·`*2.xlsx`·영상.
2. **실측과 충돌이 보이면 합리화 금지 — 사용자에게 정의를 묻는다.** "모순 아님"으로 봉합한 자리가
   가장 비싼 오류가 됐다.
3. 단정하기 전 **코드·데이터를 연다** (트윈이 뭘 하는지는 열어보면 5분이면 안다).
4. 지표 정의는 마라톤 로그 최상단에 **원본 파일 경로와 함께** 명문화한다.
