Prime Agent(오픈소스 하네스, npm 이름 `@earendil-works/pi-coding-agent`, 명령어 `pi`)를
Claude Max 구독 계정으로 로그인해서 모델을 부르면 **앤트로픽 서버가 400 오류로 거부한다.**

거부 메시지 원문:
`Third-party apps now draw from your extra usage, not your plan limits.
Add more at claude.ai/settings/usage and keep going.`

2026-08-13 01:5x 에 두 번 재현 (request_id 다름, 2.78초 만에 즉시 거부).
설치 버전 0.84.1, Node 24.15.0, Windows 11, 작업 폴더 `C:\Users\junho\prime_agent_test\`.

**Why:** 소스 코드는 구독 로그인 시 자기를 `claude-cli/2.1.75` 로 밝히고
"You are Claude Code, Anthropic's official CLI for Claude." 를 강제로 붙인다.
즉 겉보기엔 Claude Code 인 척한다. **그런데 그게 안 통한다.**
앤트로픽이 헤더 문자열 말고 다른 방법(OAuth 토큰 발급 경로 등)으로 서버 쪽에서
제3자 도구를 구분해 내고 있다는 뜻이다. 추가 사용분 지갑을 꺼 두면 아예 막힌다.

**How to apply:**
- 구독으로 Prime Agent 를 쓰는 선택지는 **없다.** 다시 검토하지 말 것.
- 쓰려면 추가 사용분 지갑을 켜야 하고 그 순간 토큰당 종량제다. 연구 규모로는 감당 안 됨.
- 부수 효과: 지갑이 꺼져 있으면 **실수로 돈이 나갈 위험이 0**이다. 지갑은 꺼 둔 채로 유지.
- 우회를 시도하지 말 것 — 우회가 이미 실패했고, 시도 자체가 계정 제한 위험이다.
- 같은 이유로 다른 제3자 하네스(구독 토큰 재사용형)도 동일하게 막힐 가능성이 높다.

## ★ 반대로 ChatGPT(Codex) 구독은 정상 작동한다 (같은 날 실측)

같은 프로그램, 같은 시험(로봇 실험 메모 파일 읽고 세 줄 요약), 같은 방식으로
`/login` → ChatGPT Plus/Pro (Codex) 로 로그인하니 **9.08초 만에 정상 응답**했다.
종료코드 0, 파일 읽기 기능도 정상 동작, 요약 내용도 정확했다.
쓸 수 있는 모델 7개(gpt-5.4 / 5.5 / 5.6-luna / 5.6-sol / 5.6-terra 등),
시험에 쓴 것은 `gpt-5.6-terra`. 실행 시 provider 이름은 `openai-codex`.

경고문도 없었다. Claude 로그인 때는 "추가 사용분에서 빠진다"는 경고가 떴지만
Codex 로그인에는 그런 경고 자체가 없다.

**Why 차이가 나나:** 회사 정책이 정반대다. 앤트로픽은 제3자 도구를 서버에서 막는다.
OpenAI 는 자사 개발자 페이지(developers.openai.com/community/codex-for-oss)에서
`pi` 를 **이름까지 적어가며** 지지한다고 밝혀 놨다. 기술 문제가 아니라 정책 문제다.

**How to apply:** Prime Agent 를 쓰고 싶으면 **Codex 쪽으로 쓴다.** Claude 쪽은 불가.
단, ChatGPT 구독의 자체 사용 한도는 소모될 것으로 보인다(미검증).

주의: 프로그램을 `/exit` 로 끄면 대화 이름을 짓느라 **현재 선택된 모델**을 한 번 부른다.
Claude 가 선택돼 있으면 그때 앤트로픽 400 오류가 뜬다. 이건 Codex 실패가 아니다.

## ★★ Codex 한도 소모 실측 (26.08.13 02:00~02:53)

사용자는 ChatGPT도 **최대 요금제(Pro)** 사용 중.

오늘 총 사용: 대화 20개 / 주고받기 70회 / **총 2,298,802 토큰**
(질문 586,169 + 캐시 재사용 1,622,016 + 답변 90,617). 프로그램 추정 금액 $2.68
(가격표 부정확 — 같은 토큰 수인 두 모델 금액이 25배 차이. 금액은 믿지 말 것).

**ChatGPT 사용량 화면은 22% → 22% 로 전혀 안 움직였다.** 35분 뒤 재확인해도 동일.
해석 두 가지가 남고 밖에서는 못 가린다:
 A. Pro 한도가 커서 230만 토큰이 1% 미만이라 정수 표시에 안 잡힘 (가능성 높음)
 B. 그 화면의 계량기가 이 경로를 아예 안 잡음

**★ 실용 결론: 프로그램이 스스로 남기는 대화 기록 파일
(`.pi/agent/sessions/**/*.jsonl`)의 usage 항목을 읽으면 토큰 단위로 정확하다.**
요청마다 input / output / reasoning / cacheRead / totalTokens / cost 가 다 들어 있다.

## ★★★ 한도 크기 실측 — 03:00 에 드디어 움직였다

더 태우기 시험: 12개 동시 / 생각 깊이 최대 / "설명서 전부 빠짐없이 읽어라" 지시.
**4분 27초에 8,972,747 토큰 (150 왕복). 화면 22% → 23% 로 1칸 움직임.**
초당 약 34,000 토큰을 태운 셈. 이 속도로도 막히지 않았다(속도 제한 여유 있음).

오늘 누적 최종: 대화 32개 / 왕복 220회 / **총 11,271,549 토큰** / 실제 결제 0원.

**한도 역산 (화면이 정수라 하한선만 신뢰):**
 · 보수적 하한: 1%p = **최소 450만 토큰** → 전체 한도 **4.5억 토큰 이상**
 · 중간 추정: 1%p ≈ 900만 토큰 → 전체 약 9억 토큰
 · 230만 토큰으로 안 움직였던 앞선 관측과 앞뒤가 맞는다.

**→ 실용 판정: 연구 규모로 한도 걱정 없다.** 하루 종일 빡세게 굴려도(왕복 300~500회,
1,500만~3,000만 토큰) 2~7%p 수준. 게다가 주 단위로 초기화된다.

단, 관측 1회에 기댄 역산이라 정밀도는 낮다. 앞으로 쓸 때마다
"기록의 토큰 수 ↔ 화면 퍼센트"를 대조하면 정확해진다.
그리고 **실제 벽에 부딪혀 본 적은 없다** — 벽의 위치는 여전히 모른다.

주의: 배경으로 여러 개 돌리다 중단하면 `node.exe` 가 살아남는다.
`Get-WmiObject Win32_Process -Filter "Name='node.exe'"` 로 명령줄에 작업 폴더가
들어간 것을 찾아 종료할 것 (오늘 1개 남아 있었다).

★★ 눈덩이 효과 실측: 파일을 읽히면 총량이 폭증한다.
 · 파일 안 읽힘, 7건 1왕복  → 52,875 토큰
 · 파일 읽힘,  8건 57왕복  → 2,241,616 토큰 (**42배**)
 답변으로 받은 글은 4.3만 토큰뿐인데 총량은 224만. **98%가 "질문 재전송"이다.**
 한 작업이 파일을 14번 왕복하며 혼자 714,026 토큰을 썼다.
 → 실제 연구 작업 비용을 추정할 때 답변 분량으로 잡으면 40배 과소평가한다.

동시 실행: 바깥에서 여러 개 던지면 진짜 병렬로 돈다.
 7개 → 개별 합 675초 vs 실제 151초 (4.5배). 8개 → 897초 vs 147초 (6.1배).

## ★★ 기능 한계 — 마라톤 작업에는 못 쓴다 (26.08.13 실측)

공식 설명서 `docs/usage.md` 303줄 "Design Principles" 원문:
"It intentionally does not include built-in MCP, sub-agents, permission popups,
plan mode, to-dos, or background bash."

즉 **일부러 뺀 것들**: 하위 작업자 / 배경 실행 / **권한 확인 창** / 계획 모드 /
할 일 목록 / 외부 도구 연결(MCP). 만들어 붙이려면 직접 확장을 짜야 한다.

내장 도구는 7개뿐: read, bash, edit, write, grep, find, ls.
하위 작업자를 만드는 도구가 아예 없다.

**★ 가장 중요한 위험: 권한 확인 창이 없다.**
Claude Code 는 명령 실행 전에 물어본다. pi 는 안 묻고 그냥 실행한다.
명령 실행 기능(bash)과 파일 쓰기·수정 기능이 기본으로 켜져 있다.
→ 연구 폴더에서 그냥 켜면 안 된다. 반드시 `--tools read` 로 읽기만 허용하거나
   격리된 폴더에서만 쓸 것.

대화 이어가기(`--continue` / `--resume`)는 된다. 대화 기록이 파일로 남는다.

★ 정정(사용자 지적): "터미널 닫으면 죽으니 밤샘 작업에 못 쓴다"는 비교는 **틀렸다.**
Claude Code 도 터미널을 닫으면 똑같이 죽는다. 그 항목은 차이가 아니다.
진짜 차이는 **긴 명령을 뒤에 돌려놓고 그동안 다른 일을 할 수 있느냐**다.
Claude Code 는 된다(끝나면 알림). pi 는 배경 실행 기능이 없어서 끝날 때까지 멈춘다.
그리고 사용자의 긴 계산은 원래 .bat 더블클릭으로 자기 창에서 따로 도니
어느 쪽 도구와도 무관하다.

폴더 안내 문서 자동 읽기는 **실증 확인**: `AGENTS.md` 에 암호를 적어 두고
도구를 전부 끈 채(`--no-tools`) 질문했더니 답변 맨 앞에 그 암호가 나왔다.
시작할 때 프롬프트에 자동으로 넣는다는 뜻.

미해결(3번 찾다 중단): 시작 화면에 뜨는 기능 묶음 목록
(computer-use / find-skills / orchestration)의 출처를 못 찾았다.
`~/.claude/skills` 에는 orca-cli 하나뿐이고 pi 패키지 안에도 skills 폴더가 없다.

## 부수 발견

`pi` 는 시작할 때 자기 폴더 바깥의 Claude Code 설정 폴더까지 읽어서
기능 목록(skills)을 가져온다. 폴더 안내 문서(CLAUDE.md / AGENTS.md)도 기본으로 읽는다.
설정 저장 위치는 환경변수 `PI_CODING_AGENT_DIR` 로 작업 폴더 안에 가둘 수 있다.
