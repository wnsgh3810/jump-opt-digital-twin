### ★ 갈래 A — 게인이 높을수록 토크가 안 맞는다 (폐루프)

즉 고게인에서 토크가 안 맞는 것은 토크 모델이 나쁜 게 아니라 **각도의 작은 오차가 크게 증폭**된 것이다.
기록에도 같은 진단이 있다 (`DEPLOY_VS_NOW.md`): "무릎 각도가 0.6도 앞서 있는 것이 전부였다.
게인 250 × 각도 오차라 1도도 안 되는 차이가 2Nm 를 만든다. 시간으로 환산하면 **2.5ms**.
**다음 작업의 1순위 과제로 등록**했다."
⇒ **토크를 고치려 하지 말고 타이밍을 고쳐야 한다.**

# 6. 판정을 수치와 연결 — **이 연구 최초의 절대 합격선** (08-12)

3. 사용자 재반박 — *"그건 한 데이터 한정으로 파악한 내용 아니냐"* → **맞는 지적이었다.**

### 자를 어떻게 골랐나 — 사용자 육안 판정 전체를 재현하는 능력으로

그리고 이게 **한 데이터 한정이 아니다.** 전 trial 평균으로 창을 5등분하면 오차 제곱합이

⇒ **하나만 넣는다. 사용자 결정: 힙 각도 오프셋.**

이유는 물리적으로도 맞다 — 힙 각도를 돌리면 **다리 전체가 돌아 발끝도 같이 옮겨진다**
(1도 = 발 4.4mm). 즉 힙 각도 축 하나가 발끝 위치 어긋남까지 포함한다.

### 구현 규칙 — 채점은 건드리지 않는다
내가 "각도 오프셋을 넣으면 채점이 어긋난다"고 우려했는데, **출력 단계에서 빼면 해결된다.**
```
물리 계산 : 관절을 (측정 각도 + 오프셋) 자리에 놓는다      ← 중력·접촉이 실제 자세로 계산됨
제어 계산 : 목표도 (측정 목표각 + 오프셋) 으로 준다        ← 제어기가 보는 값은 그대로
기록 출력 : 오프셋을 도로 빼서 남긴다                      ← 채점은 지금 코드 그대로
```
이렇게 하면 **각도 채점은 한 자리도 안 바뀌고, 물리만 오프셋을 반영**한다.
오프셋 0 이면 지금과 완전히 같은 결과가 나와야 한다 — 이걸 첫머리에서 확인할 것.

### 범위와 판별 규칙
· 범위 **±1.0도** (발끝으로 치면 ±4.4mm). 좁게 두는 이유는 §8-1 과 같다 —
  넓게 열면 답이 경계로 밀리며 헛것을 잡는다.
· 실측 검증상 발 위치가 육안과 1~3mm 안에서 맞았으므로 참값은 ±0.7도 안쪽일 것이다.
| 결과 | 뜻 |
|---|---|
| 0 을 고름 | 자세는 문제없다. 지금 모델 정당 |
| 0 이 아닌데 허벅지 무게중심이 CAD 쪽 복귀 | 무게중심이 자세 어긋남을 대신 삼키고 있었다 |
| **경계(±1.0도)에 붙음** | 다른 결손을 대신 삼키는 중 — 범위를 넓히지 말고 무엇을 삼키는지부터 볼 것 |
| 점수는 좋아지는데 검증용 데이터 악화 | 진짜 물리가 아니다 — 뺀다 |

### 미해결 (다음에 확인)
위 표에서 **무릎 토크가 전부 0.000** 인데, 발이 옆으로 가면 무릎 주위 모멘트 팔도 변하므로
물리적으로는 0 이 아니어야 한다. 지면 반력을 관절 토크로 옮기는 내 계산(자코비안 전치)이
무릎 쪽을 제대로 못 잡고 있을 가능성. **힙 쪽 결론(두 축이 같은 모양)은 이것과 무관하게
성립**한다 — 근거가 세 경우의 비율이 같다는 것이고 그건 힙 값만으로 나왔다.
