## 4. 데이터 함정 — 어기면 결과가 통째로 무효

1. **발밑 힘센서(GRF)**: 측정이 부정확하고 **세션마다 교정이 다르다.**
   → **힘의 크기를 어디에도 쓰지 말 것. 세션 간 비교도 금지.**
   허용되는 것은 "닿았나 안 닿았나"와 상대 타이밍뿐이고, 그마저 **고정 문턱 금지** —
   각 trial 이 자기 창의 낮은/높은 무리 중간값으로 판정 (`_GH8_statics.plateaus`).
2. **`currentTorque` = 모터에 내린 명령**이다. 축에서 잰 값이 아니다. 단위는 N·m.
   12비트 ±18 N·m 로 감기고 MATLAB 이 푼 결과라 |값|>18 이 나온다.
   ⇒ **축 토크의 실측은 존재하지 않는다.** 고속 손실(역기전력·토크상수 처짐·감속기 효율)은
   이 채널로 **원리상 관측 불가**.
3. **목표각(desiredAngle) 채널은 실제보다 2샘플(4ms) 먼저 기록된다.**
   채널을 교차해 계산할 때 반드시 되돌릴 것 (미보정 시 25~30% 과대).
4. **0424 이전 전 세션은 목표 속도를 0으로 넣고 제어했다** (26.03.19 · 26.03.24 · 26.04.21).
   판정 함수 `fs_data.vdes_applied(sess)` 가 날짜로 처리한다.
5. **26.03.24 는 검증 전용.** 적합에 넣으면 안 된다. 게인이 폴더에 안 적혀 있어
   PD 흉내 채점은 못 돌린다 (측정 토크 주입 재생만 가능).
6. **`26.03.24/Jump/harness_output/` 은 합성 데이터** — 분석 사용 절대 금지.
7. **0324 · 0422 · 0421 · 0319 의 `jump_opt_compare/predicted_compare.csv` 는 토크가
   1.3~1.36배 오염** — 사용 금지, xlsx 직행.
8. **영상 자 = 발 금속판 30.0 mm.** 영상마다 그 영상에서 재측정할 것 (카메라 거리·줌 상이).

### 5-2. 미해결 문제
1. **명령→축토크 환산이 평평하다.** 모델은 어느 크기에서나 0.65~0.68. 실측은
   작은 명령 **1.26**(분동) / **1.23·1.42**(매달림 운동방정식 적합, 독립 2경로) →
   큰 명령 **0.86**. 매달림 구간에서 **1.9배 어긋난다.** ★ 최대 결함.
   ☠ 손으로 실측값을 넣으면 **양쪽 판이 다 나빠진다** (점프 0.1944→0.2505) — 마찰·관성이
   이미 흡수해 놓았기 때문. **반드시 같이 재적합해야 한다.**
2. **속도에 비례하는 저항이 5~16배 부족.** 실측 0.038~0.114 vs 모델 0.0071 [N·m/(rad/s)].
   정체가 마찰이 아니라 **역기전력**(빨리 돌수록 같은 명령에 힘이 약해짐)일 가능성.
   단, 고속 외삽 모형은 과거 2회 기각됐다 (§6).
3. **힙 회전관성 17% 부족** (실측 0.0701 vs 모델 0.0580). 모터축 관성 0.010 → 자유 흔들림
   실측 0.0164 와 방향 일치.
4. **무릎의 운동방정식 분해가 미완.** 4절 링크 때문에 무릎 모터축 좌표에서 역동역학이
   성립하지 않아 결과가 무의미했다 (비율 54.6, 저항 −504). **폐쇄 링크를 제대로 푸는
   별도 계산이 필요하다.** 점프의 토크 오차가 주로 무릎에 있으므로 중요도가 높다.
5. **총질량이 상한(3.30)에 붙는다** — 세 판 연속. 경계 포화는 물리 결손의 신호다.
6. **이륙 직전 20% 구간이 8~12% 악화**된 채 남아 있다 (새 자가 앞 80%만 보는 대가).
7. **짐 지고 일어서기 예측이 나쁘다** — 최종 목표 중 하나인데 아직 못 맞춘다.
8. **수평 점프는 아직 손도 못 댔다.**

- **경계 포화 시 범위를 넓히지 말 것** — "이 축이 무엇을 흡수 중인가"를 먼저 판별.
- **상대 기준(그 전 모델 대비)은 절대 실패를 못 본다** — 변속기 24배 오차가 계속 통과했다.

## 8. 보고 형식 (사용자 지시, 예외 없음)

**순서**: 결론 한 줄 → 적용/미적용 before-after 표 → 전 후보 판정표 → 발견 →
결정 대기 → 이월 → 랩업 상태.

**단어**: 고등학생이 아는 일상어이거나, 로봇·물리 대학원생이 아는 표준 용어여야 한다.
그 사이의 것 — **내가 지어낸 비유**와 **저장소 안에서만 통하는 이름**이 문제다.
- 코드 이름(환경변수·함수·파일·내부 변수)은 **"하는 일"로 부르고** 이름은 괄호에 한 번만.
  나쁨: "발이 붙었다 미끄러졌다 하는 코드가 FS_MU 를 덮어쓴다"
  좋음: "발이 붙었다 미끄러졌다 하는 걸 흉내내는 코드가, 계산 단계마다 마찰값을 다시
  써넣는다. 그래서 시작할 때 정해 둔 마찰값은 지워진다."
- **내가 만든 양(기호든 한글 이름이든)은 쓸 때마다 네 가지를 붙인다**:
  ① 무엇을 무엇과 비교했나 ② 어떻게 계산했나 ③ **완벽하면 얼마인가** ④ 물리적으로 무슨 뜻인가.
  앞에서 정의했어도 다시 쓴다. 표의 항목 이름은 혼자 읽히므로 특히 조심하고 단위를 적는다.
- 설명을 압축하지 말고 과정을 문장으로 다 쓴다. 숫자에는 "그래서 무슨 뜻인지" 한 문장을 붙인다.
- 틀렸던 것·불확실한 것은 숨기지 말고 그 자리에서 밝힌다.

## 9. 일하는 방식 — 이 연구에서 실제로 사고를 막았거나 냈던 것들

1. **판별 실험 우선.** 최적화 전에 진단한다. 구간 분해·정적 감사·에너지 원장으로 오차의
   "모양"을 먼저 특정한다.
2. **부호·규약 의심은 모델 없이 검사한다.** 재생(시뮬레이션)으로 판정하면 내 코드의 결함이
   부호처럼 보인다. 실제로 그래서 틀린 보고를 냈다. PD 제어 세션이면
   `토크 = 게인×(목표각−실제각) − 감쇠×속도` 를 회귀해 **기울기 부호**만 보면 된다.
3. **검사는 채점에 쓰는 구간으로 잘라서 한다.** 기록 전체 통계는 안 쓰는 데이터까지 섞는다.
   이것 때문에 멀쩡한 세션을 "깨졌다"고 잘못 보고했다.
4. **파라미터 하나만 실측값으로 바꾸면 대개 나빠진다** — 다른 값이 이미 그 오차를 흡수해
   놓았기 때문. 실측값은 **탐색 축의 범위와 출발점**으로만 넣고, 탐색이 같이 재조정하게 한다.
   **탐색이 실측을 모른 채 그 근처에 앉으면 그것이 독립 확인이다.**
5. **침묵 실패 방역.** 여러 파일을 고치는 스크립트는 **결과를 파일에서 되읽어 확인**할 것.
   실제로 함수를 안 만들고 호출부 8곳만 바꿔 놓고 넘어가, 폐루프 채점이 전멸한 적이 있다.
   환경변수를 새로 쓰면 **지우는 목록에도 반드시 추가**할 것 (직전 평가값이 살아남는다).
6. **돌고 있는 계산에는 코드 수정이 안 들어간다.** 파이썬은 시작할 때 한 번 읽는다.
   탐색을 시동한 뒤 코드를 고치면 그 판은 옛 코드로 끝까지 돈다.
7. **긴 탐색 전에 반드시 심판을 먼저 측정한다.** 매달림 판의 첫 값 6.01 이 이상해서 파고들어
   "계산 도중 로봇 전체가 자유낙하하던" 결함을 찾았다. 그냥 돌렸으면 8시간을 날렸다.

## 10. 당신의 산출물

1. **전수 재독 후 재판정**: 지금 목록(§5-2)이 맞는가? 우선순위가 맞는가?
   빠진 것·틀린 것을 찾아 고쳐 제시하라. 근거 수치를 반드시 붙일 것.
2. **미해결 문제 해결**: 특히 ①환산 모양 ②무릎의 운동방정식 분해(4절 링크)
   ③속도비례 저항의 정체 ④총질량 경계 포화.
3. **실험 설계**: 장시간 탐색 판(.bat). 오래 걸려도 된다. 다만 **심판이 옳은지 먼저 측정**하고,
   무엇을 축으로 열고 무엇을 고정하는지 근거를 대라. 경계는 실측·설계공차에서만 유도.
4. **코드**: 정본 파일을 직접 수정. 사본 금지.
5. **최종 검증**: 짐 지고 일어서기 · 수직 점프 · **수평 점프** 세 가지 모두에 대해
   예측이 성립하는지 보이는 게이트를 설계하고 통과시킬 것.
   (수평 점프는 데이터가 없을 수 있다 — 그렇다면 "무엇이 있으면 검증 가능한지"를 명시하고,
   현재 데이터로 가능한 최대치를 정의해 그것으로 판정하라.)

**새 로봇 실험은 없다.** 부족한 것이 있으면 "이 데이터로는 여기까지"라고 한계를 명확히
적고, 가진 것 안에서 최선을 설계하라.
