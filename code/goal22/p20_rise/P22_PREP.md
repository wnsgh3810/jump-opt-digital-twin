# P22 준비 문서 — "P19를 넘어서기" 마라톤 사전 조사 종합 (2026-07-16)

발단: 사용자 지시 "프리로드 같은 편법 말고 제대로 원인을 파악해서, 모델·방법론·오픈소스 총동원,
시간/토큰 무제한, P19보다 개선". 4건 병렬 조사(문헌 2 + 데이터 판별 3종) 완료.
판별 결과 상세는 HYPOTHESES.md "P22 프리플라이트" 절, 스크립트는 p22_probe_t1/t2/t3.py.

## 확정된 출발점 (판별 라운드의 산물)

1. **푸시 부족분(+2~3Nm)은 플랜트 문제다** — 에너지 원장(T3): 측정 전류의 일이 실측 점프를
   설명하기에 충분 (0424/0602 수지 정합). 측정 과소보고 아님. 트윈이 에너지를 과잉 소산/오배분.
   P20c가 감쇠를 깎자 재생이 좋아졌던 것과 같은 방향 — 단 CL을 지키며 깎을 좌표를 몰랐던 것.
2. **관성 널스페이스가 파레토 벽의 유력 기전** — 2R 다리의 식별 가능한 관성 조합(베이스 파라미터)은
   4~6개뿐인데 우리는 나사 20+개를 돌림. 남는 자유도가 두 목적을 서로 팔아먹는 통로.
3. **0421 로더 인공물 (1.35×)** — 기준선 층이 전 세션 보편일 가능성. Phase 0에서 소스 통일 필수.
4. **0429 에너지 잉여 +40%** — 언랩 과복원/포화영역/CVT 손실. 언랩 감사(P20 잔여 카드) 우선순위 상승.
5. 죽은 축 추가: 열/배터리(T2+문헌 부호 반대), 명령 에코설(펌웨어 코드 검증), 모터측 a_hat 재교정
   (T1이 게이트 검정력 재확인).

## 로드맵 (게이트식)

- **Phase 0 — 재베이스라인 (필수 선행)**: ① 0421 토크 소스를 xlsx로 통일 (csv 출처는 사용자 확인)
  ② 언랩 감사 마무리 (0429 잉여의 데이터 오염 여부) ③ 골든 재현 재실행 → P19 지표 재산정
  (0421 항목이 움직일 것) ④ 지표 v5 선고정: v4 + 통짜 재생 dq + 점프높이 게이트.
- **Phase 1 — 베이스 파라미터 분석 (기존 데이터, ~1주)**: 식별 가능한 관성 조합 산출 → 널스페이스
  방향 동결/재그룹 → 탐색 공간 3~5배 축소. 산출물: 어떤 나사가 벤치 실측 없이는 원리적으로
  미정인지의 목록 (벤치 항목의 수학적 근거).
- **Phase 2 — 재적합 재플랫폼**: mujoco.sysid(GN, 신뢰구간)로 점추정 + pymoo NSGA-II로 파레토 전선.
  목표물 = 소산 구조(감쇠·마찰·접촉)를 베이스 파라미터 좌표에서. 성공 판정: P19를 CLτ와 재생 dq
  **양쪽**에서 지배하는 점의 존재.
- **Phase 3 — PySR 잔차 발굴 (Phase 2로도 벽이 남으면)**: 마찰/액추에이터 식의 모양 자체를 데이터가
  고르게 함. PD 공선성 함정 → 발굴 항은 반드시 폐루프 재검증 (철칙 10).
- **Phase 4 — 벤치 (병행 가능)**: 링크 무게·CoM 실측 + 유지전류 매트릭스 (기존 합의) + **공중 가진
  궤적 30분** (조건수 최적화 설계 — 새 정보를 추가하는 유일한 항목) + 모터 온도/전압 기록.
