## 토크를 어떻게 비교했나 (2026-08-11 수정)
모터가 기록으로 남기는 값은 **"이만큼 힘을 내라"는 명령 하나뿐**이다.
관절에 실제로 걸린 토크는 이 데이터에 없다 — 아무도 재지 않았다.
명령을 토크로 바꾸려면 **변환식**이 필요한데, 그 변환식은 **모델의 일부**다.
배포모델은 예전 식(`a_hat`)을, 현행은 추를 매달아 교정한 식(`canon_cap`)을 쓴다.

### 무엇이 잘못돼 있었나
구판 그래프는 '실측 토크' 선을 **항상 예전 식으로만** 그렸다. 그래서 현행 모델은
자기 식으로 계산한 토크를 **남의 식으로 만든 선**과 비교당했다. 비교가 성립하지 않는다.
실제로 동역학을 하나도 섞지 않고 두 식의 차이만 재면 힙 2.16 · 무릎 3.66 N·m 가 나온다.
표에 찍히던 토크 '악화'는 대부분 이 차이였다.

### 어떻게 고쳤나
**실측 명령과 시뮬레이션을 같은 식으로 바꿔서** 비교한다 (모델마다 자기 식).
- 실제 로봇이 낸 명령 → 그 모델의 변환식 → "실제 관절 토크는 이랬을 것이다"
- 시뮬레이션이 스스로 계산한 명령 → 같은 변환식 → "우리 모델의 예측"
두 선이 겹치면 **내 궤적·게인을 실제 로봇에 넣었을 때 계획대로 된다**는 뜻이다.
변환식이 양쪽에 똑같이 들어가므로 변환식 논쟁이 비교에 끼어들지 않는다.
→ 그래서 토크를 판정에 **다시 넣었다** (구판의 'τ 제외' 방침은 철회).

### 이 그림으로 알 수 있는 것과 없는 것
| | 알 수 있나 |
|---|---|
| 동역학·제어가 실제와 맞는가 | **알 수 있다** ← 지금 필요한 것 |
| 변환식 자체가 맞는가 | **알 수 없다** |

변환식이 30% 틀려도 양쪽에 똑같이 들어가 두 선이 함께 움직인다. 그러니 이 그림이 잘
맞는다고 해서 "관절 토크 예측이 정확하다"고 말하면 안 된다. **"명령을 의도대로 만들어내고
있다"** 까지가 보증 범위다. 변환식 검증은 **추를 매단 교정 실험**에서 따로 할 일이다.

한 가지 더: 각 모델이 자기 식을 쓰면 **기울기가 완만한 식이 조금 유리**하다. 같은 명령
오차라도 가파른 식을 쓰면 토크 오차가 크게 나온다. 현행 식이 더 가파르다 — 작지만 있는 효과다.
