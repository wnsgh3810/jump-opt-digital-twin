# 슬립·구름 전수 측정 — 최종 보고 (2026-08-09)

**대상: 영상이 있는 55 trial 전수 (10개 세션)** · 측정 성공 55/55 · QC 무경고 40/55
**육안 검증 220컷 전수 확인** (세션당 한 장짜리 시트, `03_proof/_세션한장검증/`)

---

## 결론 한 줄
발 슬립은 **두 개의 다른 양**이다 — **하강 슬립 = "그날 바닥"의 세션 상수**(재현성 0.4~1.3mm),
**푸시 슬립 = 게인에 비례하는 물리량**이지만 **59fps 영상에서만 잴 수 있다**.
그리고 **CVT 는 슬립을 바꾸지 않는다** (앞서 보인 "3배"는 계산 버그였다).

## 1. 무엇을 했나 (고등학생 눈높이)

로봇 발은 **바퀴**다. 발이 옆으로 이동했다면 두 가지가 섞여 있다.

- **구름**: 바퀴가 굴러간 것 — 미끄러진 게 아니다
- **슬립**: 바퀴가 헛돈 것 — 이게 진짜 미끄러짐

둘을 나누려면 두 개의 눈이 필요하다.

| 눈 | 알려주는 것 | 못 알려주는 것 |
|---|---|---|
| 엔코더(관절각) | 얼마나 **굴렀나** (4절 링크 폐쇄로 결정) | 실제로 얼마나 **갔나** |
| 영상(롤러 중심 추적) | 실제로 얼마나 **갔나** | 얼마나 굴렀나 (롤러에 마커가 없다) |

```
슬립 = (영상으로 잰 실제 이동) − (엔코더로 계산한 구름)
     = Δx_영상 − r · Δθ_엔코더,     r = 20.0 mm
```

자(mm/px)는 **발의 금속 원판 30.0mm** 를 쓴다 — 발과 같은 깊이라 원근 왜곡이 없다.
그리고 **영상마다 다시 잰다**: 같은 발이 화면에서 26px 이기도 61px 이기도 하다.

## 4. 발견

### 발견 1 — 하강 슬립은 온도계다 (세션 상수)
세션 **안에서 0.4~1.3mm** 로 재현되는데 **세션 사이는 −13.1 ~ +7.1mm (폭 20mm)** 다.
신호/잡음 약 15:1. 게인을 60→250 으로 7단계 바꿔도 거의 안 변한다.
⇒ **그날 바닥이 얼마나 미끄러운가**를 재는 양이다. 지표로 쓰기 좋다.

### 발견 2 — 푸시 슬립은 게인에 비례한다. 단 59fps 에서만 보인다
전 세션 중 QC 무경고 9/9 인 **26.04.24 (4K 59fps)**:

| kp1 | 60 | 90 | 120 | 150 |
|---|---|---|---|---|
| 푸시 슬립 [mm] | +2.8 / +4.6 | +3.4 | +7.3 / +7.8 / +7.8 | +6.5 / +7.1 / +7.7 |

**r = +0.81, 기울기 +0.044 mm/kp**, 그리고 **kp1 ≈ 120 에서 포화**한다 — 마찰 한계의 서명이다.

24fps 에서 안 보인 이유: 푸시가 **5프레임**뿐이라 동기 ±1프레임이 **±8~10mm** 를 흔드는데
게인 효과는 **~5mm** 다. 잡음이 신호보다 컸다. 59fps 는 푸시가 15프레임이라 ±4mm 로 떨어진다.

**같은 로봇, 다른 제어**: 0421(위치제어, dq_des=0)은 kp 60→200 전 구간에서 푸시 슬립 ≈ 0
(−2.7 ~ +1.0). 부드럽게 밀면 안 미끄러진다.

### 발견 3 — "CVT 가 3배 미끄러진다"는 계산 버그였다
0429(CVT)와 0424(무변속)는 게인 표가 겹치는 유일한 쌍이다. 보정 전에는 **7/7 이 +17mm 씩**
벌어져 "CVT 는 3배 미끄러진다"로 보고하기 딱 좋았다.

그런데 **영상 Δx 는 같았다** (−11.5 vs −11.8). 벌어진 건 **구름 항**뿐이었다 (−19.3 vs −36.7).
원인은 `Reduced._fw` 의 `knee = crank` — 이건 **l_i=30 에서만 참**이다.
l_i=25.08 에서는 무릎각이 최대 18° 어긋나고 전달비가 0.83 → 0.09 까지 변한다.

폐쇄 솔버로 고친 뒤 (l_i=30 에서 기존과 **차이 0** 으로 회귀 검증):

| 게인 | 하강 0424 → 0429 | 푸시 0424 → 0429 |
|---|---|---|
| 60_0.75_60_2 | −4.2 → −2.3 | +2.8 → +2.4 |
| 120_2_120_2 | −4.6 → −3.1 | +7.8 → +7.1 |
| 150_2.2_250_3 | −3.3 → −2.8 | +7.1 → +6.7 |
| (세션 중앙) | **−3.6 → −3.5** | **+7.1 → +6.7** |

(l_i 는 trial 마다 `Clutch.xlsx` 실측 중앙값 25.075~25.102mm — 세션 상수 아님)

⇒ **발 슬립은 변속비가 아니라 그날 바닥과 푸시 세기로 결정된다.**
   (트윈 관점: CVT 세션이라고 마찰을 따로 잡을 필요가 없다 — 자유도 한 축이 줄었다)

### 발견 4 — 자동 발탐색의 진짜 상대는 볼트가 아니라 종아리 링크
반지름을 ±25% 로 묶어 볼트를 배제한 뒤에도 6/6 이 틀렸고 전부 **링크의 밝은 가장자리**였다.
두 개의 **절대** 판별자로 갈렸다:
- **내부 게이트** — 발은 균일한 금속 원판이라 안쪽(0.62~0.78R)에 경계가 없다 (정상 −7~−21 vs 오탐 +11↑)
- **밝기 게이트** — 발은 **어두운 바닥 위의 밝은 원판** (안−바깥 평균밝기 ≥ 25)

밝기 게이트가 없으면 "흰 플랫폼 × 검은 매트" 경계에 진다 — 그 원도 안쪽이 균일해서
내부 게이트를 통과한다 (0727 에서 7/7 이 이 함정에 빠졌다).

### 발견 5 — 현행 심판은 하강을 볼 수 없다
J_G 의 채점 창(plot_window)은 길이 **0.16초**인데 하강 시작은 그보다 **3.8초 앞**이다.
그리고 개루프(ModeA) 재생은 하강 2.4~3.9초를 못 버틴다 (q1 RMSE 18~26°, q2 29~40°).
⇒ 하강 슬립을 채점하려면 **심판 층을 CL(폐루프)로 옮겨야 한다**.
   다행히 `rollout_cl_fs` 는 이미 `fx`(발 x)와 `slipv`(접촉 접선속도)를 로깅한다 —
   구현 경로는 뚫려 있고 남은 건 설계 결정이다.

## 5. 결정 대기 (사용자)

1. **심판을 CL 로 옮길 것인가** — 하강 슬립 채점의 전제. ModeA 는 점프창에서만 유효하다.
2. **Ê_slip 재정의 채택 여부**
   ```
   Ê_slip = mean_세션 |하강슬립_sim,중앙 − 하강슬립_영상,중앙| / mean_세션 |하강슬립_영상,중앙|
   푸시 성분은 59fps 세션(0424·0429·0421)에서만, 게인 기울기로
   ```
   현행 동결 최적의 그림자 점수 **Ê_slip,신 = 2.68** (CVT 세션 제외 · 9세션) —
   sim 은 세션 무관 −9~−16mm 를 내놓는데 실측은 −13.1~+7.1mm 로 흩어진다
   (마찰 자유도가 상수 1개뿐). 가장 잘 맞는 세션은 0421(차 +1.2)·0602(차 −0.1).
3. **r 통일 + 기준 재계산** — 보드 문서는 21mm, 실측은 20mm. 기준 p24 가 21mm 로 계산돼 있어
   분자·분모의 r 이 다르다. 재계산하면 p24 기준선이 바뀐다 (지표 변경이므로 승인 필요).
4. 하강 슬립 **부호가 세션마다 뒤집히는** 원인 (설치 방향? 바닥 기울기?) — 추가 조사 여부
