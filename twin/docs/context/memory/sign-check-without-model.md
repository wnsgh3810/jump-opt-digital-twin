부호가 뒤집혔는지 의심될 때 **시뮬레이션을 돌려서 판정하면 안 된다.** 내가 그렇게 했다가
틀린 판정을 사용자에게 보고했다 — 같은 파일·같은 창·토크 부호 그대로 두고 **내가 만든
공중 흉내만 켜고 꺼도 답이 뒤집혔다** (0319 공중: 켬 +211.92도 / 끔 +20.30도, 실측 −27.30도).

**Why:** 재생은 토크를 두 번 적분하므로 내 코드의 어떤 결함도 부호처럼 보인다. 데이터를
재려면 데이터만 써야 한다.

**How to apply:** PD 제어 세션이면 `토크 = 게인 × (목표각 − 실제각) − 감쇠 × 속도` 를 회귀해
**기울기 부호**를 본다. 양수면 정상. 모델도 적분도 안 쓴다 (목표각 4ms 선행 스큐는 되돌릴 것).
사용자가 먼저 제안한 방법이고 내 것보다 나았다.

이 시험이 전수 36 기록에서 부호 이상 0 을 확인했고, 덤으로 두 결함을 잡았다:
· **26.04.29(변속기) 확장판 파일의 무릎 토크 겹침 풀기 오류** — 확장판(*2/*3)이 원본과
  **정확히 +36 N·m**(12bit ±18 의 폭) 어긋난 표본을 갖고 있고, 원본에서 음수이던 표본이
  전부 양수로 바뀌어 있다 (시각 겹치는 98 개 중 8 개). 26.04.24 는 144 개 전부 일치.
  ★ **적합은 오염되지 않았다** — 현행 채점 구간이 원본 스팬과 같아서 기존 교정이 거기를
  덮는다 (구간 안 기울기 +133~+141, 설명력 0.52~0.71). 오염은 **구간 밖**에만 남아 있고
  교정이 닿을 수 없다 (원본에 그 시각이 없어 참조가 없다). 전 구간을 채점에 쓰는 순간 살아난다.
  ☠ 내가 처음에 "적합 세션이 깨졌다"고 보고한 것은 **기록 전체로 회귀한 탓**이었다 — 정정함.
  ⇒ **채점에 쓰는 구간으로 잘라서 검사할 것.** 전 구간 통계는 안 쓰는 데이터까지 섞는다.
· **26.08.02 knee250_vk118** — 힙 목표각 폭 24.00도인데 실제각 폭 67.30도 (정상 기록은 24.72도).
  힙이 명령을 안 따라간 실패 trial. 매달림 데이터에서 제외할 것.
