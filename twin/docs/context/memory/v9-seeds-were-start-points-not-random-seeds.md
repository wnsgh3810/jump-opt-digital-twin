2026-08-14 확인. 사용자가 "CMA-ES 맞냐, population 얼마냐"고 물어 코드를 열어 보다 발견.

**배포 궤적 최적화(26.07.27 실기에 넣은 계획)의 설정** — 전부 코드에서 직접 확인:
- 방법 **CMA-ES** (파이썬 `cma`) · 한 세대 후보 수 **16** · 초기 퍼짐 **0.2**(0~1 정규화 공간)
- 결정변수 **16개** = 시작 자세 2 + 매듭 14 (관절당 매듭 8개, 첫 매듭은 시작 자세에 묶임)
- **313 세대 · 5,009 회 평가 · 8.0 분** · 실행 4개(v9a~d) 중 v9d 채택
- PD 게인 힙 150/2.2 · 무릎 250/3.0 (실기와 동일) · 명령 ±35.5 자름 · 축 15 N·m는 벌점만

⚠ **틀리기 쉬운 두 가지 (내가 실제로 틀렸다):**
1. **"시드 4개"는 난수 씨앗이 아니다.** 난수 씨앗은 `11 + 재시도 라운드 번호`이고 네 실행 모두
   라운드 0에서 끝나 **씨앗은 전부 11**. 달랐던 것은 **출발점**(환경변수로 지정한 이전 계획 파일).
   ⇒ 이 네 결과는 "알고리즘의 무작위성이 답을 얼마나 흔드는가"를 **재지 못한다.**
2. **로그의 `seed: 기존 t0nc_cl.npz 매듭` 은 고정 문자열**이라 실제 읽은 파일과 무관하다.
   진짜 출발점은 같은 줄의 **시작 자세 값**으로만 구별된다.

**Why:** 출발점이 다르면 다른 봉우리로 간다 — 실제로 4개 중 1개(v9c)가 15% 나쁜 자리에 갇혔고,
나머지 셋도 0.864/0.865/0.878 로 1.6% 벌어졌다. 세대 수는 충분했다(마지막 25세대 개선이
전체 변화폭의 0.05% 이하). **부족했던 것은 세대가 아니라 출발점·씨앗의 다양성이다.**

**How to apply:** 새 계획을 짤 때 ① 출발점 8~12개 ② **난수 씨앗도 같이 바꾼다**
