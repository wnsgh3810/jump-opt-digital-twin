## 1. Prime Agent 요금 조사 — 결론: Claude 구독으로는 못 쓴다

### 무엇을 했나

오픈소스 에이전트 도구 Prime Agent(npm 이름 `@earendil-works/pi-coding-agent`, 명령어 `pi`)를
격리 폴더에 설치하고, **Claude Max 구독으로 요금이 빠지는지** 실제로 켜서 확인했다.

### 확정된 사실

| 로그인 | 결과 |
|---|---|
| Claude Max 구독 | ❌ **앤트로픽 서버가 400 오류로 거부** (2회 재현, 요청번호 다름) |
| ChatGPT(Codex) 구독 | ✅ **정상 작동** (9.08초, Opus 5 대응 모델로 정확한 요약) |

거부 문구: *"Third-party apps now draw from your extra usage, not your plan limits."*

**중요**: 그 도구의 소스 코드는 구독 로그인 시 자기를 `claude-cli/2.1.75` 라고 밝히고
"You are Claude Code..." 를 강제로 붙인다. 즉 **Claude Code 인 척한다.** 그런데 **그게 안 통한다.**
앤트로픽이 헤더 문자열 말고 다른 방법으로 제3자 도구를 가려낸다.

정액 몫이 **75%** (25% 남음)인데도 거부됐다. 즉 "한도가 모자라서"가 아니라
**제3자 도구는 애초에 정액 몫을 쳐다보지도 않는다.**

### ChatGPT 쪽 한도 소모 실측

| 시험 | 토큰 | 화면 표시 |
|---|---|---|
| 짧은 요약 2건 | 5만 | 22% → 22% (안 움직임) |
| 파일 읽기 8건 / 왕복 57회 | 224만 | 22% → 22% |
| 12개 동시 / 생각 최대 / 4분 27초 | **897만** | **22% → 23%** ✅ |

역산: **1%p = 최소 450만 토큰** → 전체 한도 **4.5억 토큰 이상**.
하루 종일 빡세게 굴려도 한 자릿수 퍼센트. **연구 규모로 한도 걱정 없다.**

★ **눈덩이 효과 실측**: 파일을 읽히면 총량이 폭증한다.
파일 안 읽힘 7건 = 5.3만 토큰 → 파일 읽힘 8건 = 224만 토큰 (**42배**).
답변으로 받은 글은 4.3만뿐인데 총량이 224만인 이유는 **98%가 "질문 재전송"**이기 때문이다.
파일 하나를 읽으면 그 내용이 다음 질문에 통째로 다시 실린다.

### 안전 관련 (반드시 알아 둘 것)

Prime Agent 는 공식 설계 원칙상 다음을 **일부러 뺐다**:
하위 작업자 · 배경 실행 · **권한 확인 창** · 계획 모드 · 할 일 목록 · 외부 도구 연결.

→ **명령 실행·파일 수정 전에 묻지 않는다.** 연구 폴더에서 그냥 켜면 위험하다.
`--tools read` 로 읽기만 허용하거나 격리 폴더에서만 쓸 것.

설치본은 시험 후 **폴더째 삭제**했다 (실제 결제 0원).
자세한 것: `docs/context/memory/prime_agent_billing_verdict.md`

그리고 **경로 정의 파일의 주석이 틀린 말을 하고 있었다**:

## 4. 저장소 뿌리를 `twin\` 에서 `CVT\` 로 올림

### 왜

Orca 는 **git 저장소만** 프로젝트로 받는다. 실제로 확인했다:

```
orca repo add --path C:\Users\junho\CVT
→ Not a valid git repository: C:\Users\junho\CVT
```

`CVT` 가 저장소가 아니어서 프로젝트 뿌리가 늘 `twin` 으로 잡혔다.
`CVT` 를 본거지로 쓰려면 저장소가 여기 있어야 했다.

### 무엇을 했나

- `twin\.git` → `CVT\.git` 이동. **폴더는 하나도 안 움직였다.**
- 추적 파일 **5,063개가 `twin/` 아래로 이동한 것으로 기록** (전부 내용 100% 동일)
  → `git log --follow <파일>` 로 이전 이력이 그대로 따라간다 (검증 완료)
- `CVT/.gitignore` 신설: `Data/` `jump_opt/` `AVT LEG/` `FKnIK/` 제외 (합쳐 56 GB)
- `jump_opt/` 와 `AVT LEG/` 안에도 각각 `.gitignore`(`*` 한 줄)를 넣어
  **어떤 저장소 안에 들어가더라도 제외**되게 했다

### 하마터면 놓칠 뻔한 것

**GitHub Actions 는 저장소 뿌리의 `.github/workflows/` 만 읽는다.**
이동하면서 `twin/.github/` 로 내려가서, 그대로 뒀으면 **문서 사이트 배포가 조용히 멈췄을 것이다.**
위로 되돌리고 안의 두 줄도 고쳤다 (`working-directory: twin`, `path: twin/site`).
실제로 배포를 돌려 **성공**을 확인했다.

### 검증

|---|---|
| 커밋 수 | 926 → 928 (작업 2건) |
| 첫 커밋 | `52d6ab6c` 동일 |

`REPO_ROOT` 는 파일 자기 위치에서 계산하므로 저장소가 옮겨져도 값이 안 바뀐다.
그래서 코드가 하나도 안 깨졌다.
